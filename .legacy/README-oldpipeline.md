# PRisma Pipeline Guide

This document contains the operational details for running PRisma analyses, generating figures, understanding PPC ranking (`z1`), filename ordering, and building gallery previews.

## Scope

The `pipeline/` folder contains:

- Retrieval runners: `run_sweep_configurable.py`, `run_sweep_parallel_configurable.py`, `run_sweep_parallel_configurable.sh`
- Analysis packages: `photoring/`, `exorings/`, `geotrans/`
- Figure generator: `generate_figures.py`
- Case data/results: `kepler_51/inputs/`, `kepler_51/results/`

From the repository root:

```bash
git clone https://github.com/seap-udea/PRisma.git
cd PRisma

python3 -m venv .venv
```

## Running the retrieval analysis

### Inputs

Kepler-51 inputs are in `pipeline/kepler_51/inputs/`:

- `ttv/<planet>/...post_equal_weights.dat`
- `observables/kepler_51_<planet>_observables.dat`
- `rho_true_data/rho_true_samples.dat`

Run products are written under `pipeline/kepler_51/results/exorings/` as:

- `<run_tag>.npz`
- `<run_tag>_meta.json`

### Preview the full campaign

From `pipeline/`:

```bash
bash bin/run_sweep_parallel_configurable.sh --dry-run --n-procs 6
```

Reference-only preview (the two manuscript runs):

```bash
bash bin/run_sweep_parallel_configurable.sh --dry-run --validate-refs --n-procs 6
```

### Launch

By default, the sweep behavior and parameters are defined in a configuration file (e.g., `run_config_full.py`).

1. Edit or create a config file to set the desired configuration (observables, free parameters, etc).
2. Launch the sweep:

```bash
nohup bash bin/run_sweep_parallel_configurable.sh --config run_config_full.py --n-procs 6 > sweep_parallel.log 2>&1 &
tail -f sweep_parallel.log
```

Useful flags:

- `--config FILE`: python configuration file to use (required)
- `--n-procs N`: dynesty worker processes per configuration
- `--jobs J`: concurrent configurations
- `--validate-refs`: only manuscript reference tags
- `--skip-ppc`: skip posterior predictive draws
- `--case NAME`: case folder under `pipeline/` (default `kepler_51`)
- `--forward-models MODELS`: forward model(s) to run (default: `exorings`). Can accept multiple models, e.g. `--forward-models exorings exorings_legacy`.

The sweep will assign a `RUN_LABEL` (e.g., `_P1`, `_P2`, `_P3`) to each custom run if specified in the config to prevent overwriting base tags.

### Stop and resume

Stop:

```bash
bash bin/stop_sweep_parallel.sh
bash bin/stop_sweep_parallel.sh --status
```

Resume: rerun the same launch command. Completed tags are skipped.

## Figure generation from saved runs

Script: `pipeline/generate_figures.py`

### Typical usage

From `pipeline/`:

```bash
python bin/generate_figures.py kepler_51/results/exorings/*.npz
```

Generate only PPC figures:

```bash
python bin/generate_figures.py kepler_51/results/exorings/*.npz --only ppc
```

Preview names without drawing:

```bash
python bin/generate_figures.py kepler_51/results/exorings/*.npz --dry-run
```

Enable TeX labels:

```bash
python bin/generate_figures.py kepler_51/results/exorings/*.npz --latex
```

Force regeneration of existing figures (by default, already-generated figures are skipped):

```bash
python bin/generate_figures.py kepler_51/results/exorings/*.npz --force
```

Generate figures without the scoring category and ranking prefix in the filenames:

```bash
python bin/generate_figures.py kepler_51/results/exorings/*.npz --no-prefix
```

`generate_figures.py` dynamically extracts the scoring category from `scoring_{case}_{planet}.json` (generated by `score_retrievals.py`). If this file doesn't exist, the script will abort unless you specify the `--no-prefix` flag.

Output directory:

- `pipeline/<case>/results/figures/`

Generated names:

- `{case}_{planet}_{catX}_{CategoryName}_{ORDKEY}-{run_tag}_corner.png`: the classic corner plot, with the median parameter values and Bayesian Evidence ($\ln \mathcal{Z}$) printed in the title.
- `{case}_{planet}_{catX}_{CategoryName}_{ORDKEY}-{run_tag}_corner_reduced.png`: a simplified corner plot without nuisance parameters.
- `{case}_{planet}_{catX}_{CategoryName}_{ORDKEY}-{run_tag}_ppc.png`: the Posterior Predictive Check comparing the model lightcurves against Kepler data.


## PPC score (`z1`) and ordering

For each observable in the PPC set
`{delta, T14, T23, rho_obs, b_obs}`:

1. Compute normalized mismatch:

$$
 w_{1,i} = \frac{W1_i}{|\langle x_{obs,i} \rangle|}
$$

2. Average across available observables:

$$
\langle w_1 \rangle = \text{mean}_i(w_{1,i})
$$

3. Define score:

$$
 z_1 = -\log_{10}(\langle w_1 \rangle)
$$

Interpretation: larger `z1` means better PPC agreement.

### `ORDKEY` structure

`ORDKEY` format:

- `ordXXXXX-z1_YY.YY`

Where:

- `z1_YY.YY` is the readable score (2 decimals)
- `ordXXXXX` is an inverted sortable bucket:

$$
\text{ord} = \text{clip}(\text{round}((100-z_1)\times 1000), 0, 99999)
$$

Because `ord` decreases when `z1` increases, alphabetical sorting puts better runs first.

If `z1` cannot be computed (for example missing PPC array), the script uses:

- `ord99999-z1_nan`

so those files go to the end.

## Multi-Metric Retrieval Classification

While `z1` is useful for comparing predictive checks, we provide a more comprehensive **Decision Tree Classification** system to determine the physical quality of a retrieval. This system assigns a mutually exclusive category to each retrieval by checking its properties sequentially. Within each category, retrievals are ranked by their PPC score ($Z_1$).

The categories are evaluated in this strict order:

1. **Rule 1: Good Average Fit (PPC)**:
   Measures the average agreement between the posterior predictive checks (PPC) and the empirical observables using the $z_1$ metric.
   - **Condition**: $z_1 \ge 1.2$
   - **If it fails**: `[Rejected] Poor Fit`

2. **Rule 2: Good Individual Lightcurve Fit (PPC Min)**:
   Ensures that no individual strict lightcurve observable (`delta`, `T14`, `T23`) has a catastrophic fit hidden by a good average. It computes the worst individual $z_1$ among these geometry variables.
   - **Condition**: $z_{1,\mathrm{min}} \ge 1.0$ (maximum fractional error $\le 10\%$).
   - **If it fails**: `[Rejected] Poor Individual Fit`

3. **Rule 3: Physical Density (Nuisance Constraint)**:
   Evaluates how well the marginal posterior of the nuisance stellar density $\rho_{\mathrm{true}}$ matches the independent empirical prior. The empirical transit impact parameter $b$ is deliberately excluded since a ringed planet's true $b$ differs from the spherical transit $b$.
   - **Condition**: Fractional error between the median $\rho_{\mathrm{true}}$ and the empirical true density must be $\le 25\%$.
   - **If it fails**: `[Rejected] Unphysical Nuisance`

4. **Rule 4: Confirmed Ring ($f_e$)**:
   Ensures the retrieval converges to a ringed model ($f_e > 1$). 
   - **Condition**: The 16th percentile of the $f_e$ marginal posterior ($f_{e,p16}$) must be $\ge 1.0$.
   - **If it fails**: `[Degenerate] Ringless`

5. **Rule 5: Stable Angles ($i_r, \theta$)**:
   Evaluates multimodality in ring orientation. The planetary period $p$ is allowed to be unstable and is ignored in this constraint.
   - **Condition**: Both angles should ideally be unimodal. Average KDE peaks $\le 1.5$.
   - **If it fails**: `[Acceptable] Multimodal Angles`
   - **If it passes**: `[Excellent] Golden Sample`

### Usage

The complete workflow to process results and generate the visual markdown report is a three-step process, since the report must embed the generated figures:

1. **Evaluate and Classify (JSON only)**
   ```bash
   python bin/score_retrievals.py kepler_51/results/exorings
   ```
   *(By default, this skips `.npz` files that are already evaluated. To force a full re-evaluation of all files, append `--force`.)*

2. **Generate Figures with Scoring Prefixes**
   ```bash
   python bin/generate_figures.py kepler_51/results/exorings/*.npz
   ```
   *(Similar to scoring, this skips figures that already exist. Use `--force` to regenerate them.)*

3. **Generate the Markdown Visual Report**
   ```bash
   python bin/score_retrievals.py kepler_51/results/exorings --report
   ```

The Markdown report groups the results from best to worst based on a Decision Tree and embeds their corresponding figures. The Decision Tree includes the Bayesian Evidence ($\ln \mathcal{Z}$) as a criterion, actively separating runs with $\ln \mathcal{Z} < 0.0$ into a "Low Bayesian Evidence" category to ensure only models that strictly improve upon the base null-hypothesis remain as "Golden Samples". Within each category, models are sorted by their Bayesian Evidence ($\ln \mathcal{Z}$).

## Why case+planet is in the prefix

The filename prefix starts with `{case}_{planet}_...` so files naturally group by planet in file browsers. Within each planet group, `ORDKEY` keeps best PPC files first.

## Gallery generation

There are two related concepts:

1. Analysis figure outputs:
- `pipeline/kepler_51/results/figures/`

2. Web gallery previews (`.webp` thumbnails):
- generated into `pipeline/kepler_51/results/figures/.gallery/`

Preview generation uses:

- config: `.seap-udea-gallery.json` (repo root)
- script: `bin/seap-udea-gallery.sh`

Run from repo root:

```bash
bash bin/seap-udea-gallery.sh
```

Optional tuning:

```bash
MAX_WIDTH=640 QUALITY=78 bash bin/seap-udea-gallery.sh
```

Notes:

- The script reads `path` from `.seap-udea-gallery.json`.
- It builds lightweight `.webp` previews in `.gallery/` next to source images.
- If naming conventions change, update `start_with` in `.seap-udea-gallery.json` to an existing file in `pipeline/kepler_51/results/figures/`.

## End-to-end example

From `pipeline/`:

```bash
# 1) Run retrievals (or skip if results already exist)
bash bin/run_sweep_parallel_configurable.sh --config run_config_full.py --n-procs 6

# 2) Build ranked figures from saved runs
python bin/generate_figures.py kepler_51/results/exorings/*.npz
```

From repo root:

```bash
# 3) Build gallery previews
bash bin/seap-udea-gallery.sh
```
